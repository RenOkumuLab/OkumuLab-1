# OkumuLab 1 開発メモ（v1.0.0）

Labium（Prinzipal 8' のフルーパイプ）の物理モデルを、C++ / JUCE 8 の VST3 とスタンドアロン（Windows x64）にしたものです。画面は WebView2 + Three.js で、C++ の音源の物理状態（ジェット、管内の定在波、壁の振動）をそのまま描きます。

このファイルは開発中の記録です（物理モデルの中身、版ごとの変更、検証の結果）。文中の `test_out/`（試験の記録と試聴用 WAV）と `tools/pluginval/` はリポジトリに含めていません。使い方とビルドの手順はリポジトリ直下の `README.md` にあります。

- 製品名 **OkumuLab 1**、バージョン **1.0.0**、メーカー **OkumuLab**
- プラグインコード `OkmL` / `Lbm1`。以前の「OkumuLab 1」v0.2.2〜0.4.0（`OkmL` / `Ok01`）とは別のプラグインとして扱われるので、それらを使っているプロジェクトには影響しません。
- v0.5.0（手順3・4）からの追加：**Mallet モード**（パイプを硬いマレットで叩く）、**WIND モードの風圧の見直し**（弱い風での音量）、**物理的な残響**（教会の身廊を計算）、**手順5**（Lab の変調の全項目、変調マトリクス、実験レシピ、最適化、pluginval）。
- v0.6.1：MIDI CONTROLLER のつまみ 5「Wind pressure」の中身を、それまでの Bellows（ふいご）パラメータにしました。1.00 = 500 Pa、0.00〜5.00 です（下の「Wind pressure（v0.6.1）」）。
- v0.6.2：DAW の中でも 3D の画面（パイプが回る画面）が開くようにしました。画面の見出しから説明の文字を除きました（下の「画面と DAW（v0.6.2）」）。
- v0.6.3：プラグインの中の人名を除きました。レシピ 1 の名前を「Prinzipal 8'」にし、その説明文からも除き、風圧つまみの緑の帯の説明は「Baroque organ examples」にしました。画面左上のロゴを「OkumuLab 1」の表記にしました（予備のネイティブ画面も同じ）。
- **v1.0.0**：Prinzipal の寸法を文献と照らし合わせ、初期値の音を含めて「ビリビリ」と聞こえていた音を直しました（下の「Prinzipal の寸法の見直し（v1.0.0）」）。風圧の基準 500 Pa、つまみ・範囲・初期値・レシピの値は同じです。右の状態表示の GAS は Gas つまみが AIR 以外のときだけ点灯し、起動時の画面のロゴは「OkumuLab 1」の表記です。
- **v1.0（公開版、バージョン表示は 1.0.0）**：音源は v1.0.0 のもの。アプリと VST3 の物理モデルに違いがないことを確かめ、ホストに左右される計算モードをアプリに合わせて統一しました（下の「アプリと VST3 の統一（v1.0）」）。ホストのバッファ長や音の始まりの位置によって雑音とピッチのずれが出る不具合も直しました（下の「ホストのブロック長によるビリビリの修正（v1.0 修正版）」）。

## ビルド

必要なもの：Visual Studio 2022（Build Tools 可）の「C++ によるデスクトップ開発」。CMake と Ninja は Visual Studio 付属のものを使います。

```
build.bat          VST3 + スタンドアロン + 試験（Release）
build.bat dsp      DSP コアと labium_check だけ（JUCE なし、数十秒）
```

- JUCE のファイル名が長いため、**短いパスに置いてビルド**してください（例：`C:\dev\OkumuLab1`）。
- 最初のビルドは JUCE ごとコンパイルするので数分かかります。`web/` だけを変えたときは zip の作り直しとリンクだけです。
- C ランタイムは静的リンクです。配布先に Visual C++ 再頒布パッケージは要りません。
- リソースコンパイラの依存関係スキャン（cmcldeps）は切ってあります（`CMakeLists.txt` 先頭）。日本語の Windows では cl.exe の「メモ: インクルード ファイル:」が rc.exe のコマンドラインを壊し、再構成のあとに RC1107 で止まったためです。
- AVX2 の内側ループ（`SimdAvx2.cpp`）だけを `/arch:AVX2` でコンパイルし、実行時に CPU を調べて使います。AVX2 のない CPU では SSE2 版が動きます。

## インストールと使い方

- **VST3**：Releases の zip にある `OkumuLab 1.vst3` フォルダを `C:\Program Files\Common Files\VST3\` にコピーし、DAW でプラグインを再スキャンします（コピーには管理者権限が要ります）。
- **スタンドアロン**：Releases の zip にある `OkumuLab 1.exe` を起動し、Options（左上）からオーディオ出力と MIDI 入力を選びます。
- 画面には **WebView2 ランタイム**を使います（Windows 11 には標準で入っています）。ない場合はネイティブ画面で開きます。WebView2 の作業フォルダは `%APPDATA%\OkumuLab\OkumuLab 1\WebView2` です（作れないときは一時フォルダ）。環境変数 `OKL_NATIVE_UI=1` で、いつでもネイティブ画面にできます。
- Windows では、MIDI 機器を同時に開けるのは1つのアプリだけです。スタンドアロンと DAW を同時に起動しないでください。

## 画面

- 上のバー：**WIND / MALLET**（吹くか叩くか）、**レシピのメニュー**（実験レシピ = DAW のプログラム）、MIDI・発音数・DSP 負荷・サンプルレート・FPS、OUT（出力レベル）、MON（MIDI モニター）、?（操作の一覧）、RESET、PANIC。
- レシピを選ぶと、何を聴けばよいかがパイプの画面の上に表示されます（クリックで消えます）。
- 左：MIDI コントローラーの8つまみ、送風、整音（ニッキングを追加）、管の形（側孔は音にも効くようになりました）、大気。
- 右：状態表示、ジェット断面（Mallet では管壁の断面）、**LAB**（物理FM の対象、クロスドライブを追加）。LAB の見出しの **MATRIX** で変調マトリクスを開きます。マトリクスがつまみを動かしているあいだは MATRIX が琥珀色に光り、動かされているつまみに琥珀色の印が出ます。
- つまみは DAW のパラメータです（オートメーション可）。**右クリックで MIDI ラーン**。ダブルクリックで初期値。Shift ドラッグで微調整。
- ブラウザ版（`web/index.html` をブラウザで開いたもの）は手順2の試作で、手順5の音の機能（ニッキング、物理FM の対象、クロスドライブ、マトリクス）はありません。画面では「PLUGIN」と表示して薄くしています。

## 画面と DAW（v0.6.2）

- **DAW の中でも 3D の画面が開きます。** 0.6.1 までは、画面を開く前の「WebView2 が使えるか」の確認を作業フォルダの指定なしで行っていました。その場合 WebView2 は DAW の exe の隣に「<exe 名>.WebView2」フォルダを作ろうとし、DAW が Program Files にあると作れずに失敗するため、予備のネイティブ画面になっていました。確認にも画面と同じ作業フォルダ（ユーザーの AppData）を使うようにしました。
- 確かめ方：サブフォルダを作れないフォルダにホスト（`okl_hosttest.exe`）とスタンドアロンを置いて起動。0.6.1 ではネイティブ画面になり（3D の画面の試験が動かない）、0.6.2 では 3D の画面が開いて試験に合格しました。
- 左上のロゴの下はバージョン（例：v0.6.2）だけにしました。
- 上のバーの WIND / MALLET のボタンは名前だけにしました（説明の文字なし、レシピのメニューと同じ高さ）。
- 01〜10 の欄の見出しは番号と名前だけにしました（例：「01 MIDI CONTROLLER」）。右側の説明（8 KNOBS など）と、07 の「true scale / exaggerated」、09 の「output · log frequency」も除きました。08 LAB の MATRIX ボタンはそのままです。Mallet では 07 の名前が WALL SECTION に変わるのも以前のままです。
- 予備のネイティブ画面（WebView2 がないときだけ使う）は変えていません。

## macOS 版と Linux 版

- **形式**：macOS は VST3、Audio Unit、スタンドアロン（Apple silicon と Intel の両方で動く 1 つのバイナリ、macOS 10.15 以降、署名は ad hoc）。Linux は VST3 とスタンドアロン（x86-64、glibc 2.35 以降）。
- **ビルド**：`bash build.sh`（Windows の `build.bat` と同じ使い方。`bash build.sh dsp` は音源と labium_check だけ）。GitHub Actions（`.github/workflows/build.yml`）が push のたびに macOS と Linux でビルドし、配布用の zip / tar.gz を作る（実行結果のページの Artifacts に 3 日間。サインインしてダウンロードする）。Releases には何も置かない。
- **CPU ごとの計算**：x86-64 は今までどおり SSE2 と AVX2+FMA（実行時に選択）。ARM64（Apple silicon、ARM の Linux）は同じ計算を素の C++ で書いた版（コンパイラが NEON にする）。浮動小数点のモード（丸めは最近接、例外はマスク、音声では非正規化数を 0 に）は `src/dsp/FpEnv.h` が x86-64 では MXCSR、ARM64 では FPCR で設定する。GCC / Clang では、ソースに書いていない積和の融合（FMA）をしない（`-ffp-contract=off`、MSVC の /fp:precise と同じ計算）。
- **画面**：Windows は WebView2、macOS は WKWebView（OS に入っている）、Linux は WebKitGTK（libwebkit2gtk-4.1、画面を開くときに読み込む。ない場合はネイティブ画面）。ページ（`web/`）は同じ。
- **Linux のスタンドアロン**：ALSA と JACK（PipeWire の JACK を含む。libjack は実行時に読み込む）。
- **未確認のこと**：macOS と Linux はビルドまでで、試験（labium_check、pluginval など）も実機で音を聴いての確認もしていない。

## ホストのブロック長によるビリビリの修正（v1.0 修正版）

- **症状**：SAVIHost（MME、44.1 kHz、バッファ 1764 サンプル）で鳴らすと、規準状態でもビリビリと鳴り、ピッチが +2.7 ¢ ほどずれ、管内の波形も乱れた。
- **原因**：パイプの計算は 32 サンプル（内部レート）ごとの制御フレームで係数を更新する。ジェットの揺らぎ（乱流）の前に置いたローパスの係数と、その遅れの補正値（と側孔の係数）だけがフレームをまたいで保存されておらず、1 回の計算呼び出しの途中でフレームが切れると、残りの部分は「ローパスなし・補正なし」で計算されていた。ジェットの遅れがそのたびに跳ぶので、雑音と音程のずれになる。
- **起きる条件**：ホストのブロック長が 16 の倍数でないとき（SAVIHost の 1764、441 など）、または鍵盤の音の始まりがブロック内の 16 サンプル単位の位置にないとき（ライブで弾いた MIDI は大半がこれ）。サンプルレートには関係しない。0.6.3 と別セッションの v1.0.0 の音源にも同じ箇所がある。
- **確かめたこと**：
  - SAVIHost の出力を録音し（WASAPI ループバック）、同じ条件（44.1 kHz、ブロック 1764）を DAW なしで再現すると、周期からのずれ −14 dB（正常は −35 dB）、倍音のあいだの成分 −18 dB re H1（正常は −42 dB）、6.25 Hz（1764 × 4 サンプル周期）の揺れまで一致した。
  - 直した版はブロック長（16、37、100、441、480、1764）によらず、持続音の出力が全サンプル一致する（`labium_check blocks`、44.1／48 kHz、側孔の開閉とも）。直す前の版ではこの検査が 480 以外で失敗する。
  - 16 の倍数のブロックで拍の頭から鳴らした音は、直す前と全サンプル同じ（その場合の音は変わらない）。
  - VST3 として読み込んで鳴らすと、直す前の VST3 は 44.1 kHz／1764 で −14 dB、48 kHz／480 でも音の始まりが 7 サンプルずれると −18 dB・+2.7 ¢。直した VST3 はどちらも −35〜−38 dB・0.0 ¢。
  - 以前 Bitwig で録った演奏でも、29 音のうち 14 音で倍音以外の雑音が 3 dB 以上多かった（5 音は 10 dB 以上）。Bitwig でのビリビリにもこの不具合が加わっていたと考えられる。
- 試験用：`okl_hosttest --render` は環境変数 `OKL_HOST_FS`・`OKL_HOST_BS` でホストのサンプルレートとブロック長を変えられる。

## アプリと VST3 の統一（v1.0）

v1.0 は、音源に上の v1.0.0 を採用した版です。

- **きっかけ**：Bitwig で鳴らすと初期状態でも「ビリビリ」と聞こえた件を、Bitwig の中で弾いた演奏を記録して調べました。Bitwig の中でプラグインが出していた音は、同じ演奏を DAW を通さずに音源で計算した音と一致し（平均 0.2 dB）、原因は Bitwig ではなく、そのとき入っていた版の音源（0.6.3 の音源：第2倍音が −26〜−41 dB と弱く、第6〜12倍音が強い）でした。同じ演奏をこの版の音源で鳴らすと第2倍音は −15〜+8 dB に戻り、第6〜12倍音は 6〜10 dB 下がります。
- **コード**：アプリ（`OkumuLab 1.exe`）と VST3 は同じソースから同時にビルドされ、物理モデル（`src/dsp`）とプラグインの処理（`processBlock`）は共通です。両者で違うのは、画面に出すホスト名と、試験モードの終わり方だけです。
- **実測**：試験用の切り替え `OKL_RENDERTEST=<記録したノート>|<出力 WAV>` で、アプリと VST3 のそれぞれが自分の `processBlock` で同じ演奏（Bitwig で弾いた 61 音、60.9 秒）を計算した結果は、**全サンプル一致**しました。プラグインの画面を開いているかどうかでも音は変わりません（一致）。
- **統一した点（浮動小数点の計算モード）**：ホストのスレッドが丸めの方式（MXCSR）を標準と違うものにしていると、同じ音源でも計算結果が変わりました（音源だけで −108 dB 程度）。音源の準備（パイプの設計・部屋の計算）、ブロックごとの処理（MIDI の処理を含む）、つまみの曲線の変換を、アプリと同じ計算モード（最近接丸め、例外はマスク、音声処理ではデノーマルを0に）で行うようにしました。標準のモードではアプリと VST3 は全サンプル一致し、ホストが一生を通して別の丸めを使った場合でも差は −110 dB 以下です（JUCE 自身が行う直線のつまみの換算の分）。
- **音は v1.0.0 と同じ**：同じ演奏を VST3 で鳴らした結果は、以前の v1.0.0 の VST3 と全サンプル一致します。
- 試験用：`okl_hosttest --render <記録> <出力> [vst3]`（記録したノートを VST3 で鳴らす）、環境変数 `OKL_HOST_ROUNDING`（プラグインを呼ぶあいだだけ丸めを変える）、`OKL_HOST_ROUNDING_ALL`（プラグインの生成から丸めを変える）。結果は `test_out/unify_v10.txt`。
- バージョン番号は 1.0.0 のままです（画面の表示も v1.0.0）。
## Prinzipal の寸法の見直し（v1.0.0）

初期値の音を含めて「ビリビリ」と聞こえ、実際のオルガンでパイプの調子が悪いときのような音になっていました。風圧の基準（500 Pa）は変えずに、Prinzipal の寸法を述べた文献をあらためて調べ、設計と照らし合わせて直しました。

### 調べた文献

| 項目 | 文献 |
|---|---|
| 標準のスケール（Normalmensur）、歌口の幅 | Töpfer の Normalmensur：8' C の内径 155.5 mm、17 番目の音で半分、歌口の幅は円周の 1/4。1927 年にドイツのオルガン評議会が 155.55 mm を標準に（[Organ flue pipe scaling](https://en.wikipedia.org/wiki/Organ_flue_pipe_scaling)、[Arndt Brünner の Mensurenrechner](https://www.arndt-bruenner.de/hausorgel/CalcMens.htm)） |
| 切り上げ（Aufschnitt） | Prinzipal 8' は歌口の幅の 1/3.4〜1/4。風圧が低いほど低く切る（[Über Labien, Aufschnitte und Kerne der Labialpfeifen](https://orgelromantik.aeoline.de/2009/02/06/uber-labien-aufschnitte-und-kerne-der-labialpfeifen/)） |
| イタリアの Principale | 歌口は円周の 1/4、口の縦横は 1:4（切り上げ ≈ 歌口の幅の 1/4）、風圧 45〜55 mmWS 程度（[Nicola Ferroni：Principi di intonazione delle canne labiali](https://www.nicolaferroni.com/blog/2009/01/31/principi-di-intonazione-delle-canne-labiali/)）。Antegnati（1565 年、マントヴァ、サンタ・バルバラ聖堂）の Principale の実測：歌口の幅 ≈ 外周の 2/9、板厚は径 140 mm で 1.1 mm、45 mm で 0.7 mm、22 mm で 0.5 mm（[実測表](https://www.antegnatisantabarbara.it/it/organo-saggi-misure.asp)） |
| 歌口のすき間（Kernspalte） | Principal の flue はおおむね下唇の板厚（[C. B. Fisk：Pipe Flueways](https://cbfisk.com/writing/pipe-flueways/)）。金属管で 0.4〜1.4 mm 程度 |
| 整音数（Ising） | 2〜3 が普通、2 前後で効率が最大、3 を超えるとオーバーブロー（[Rioux：Sound Quality of Flue Organ Pipes](http://articles.ircam.fr/textes/Rioux01b/index.pdf)、[The Art of Voicing](https://www.thediapason.com/content/art-voicing-part-1)） |
| ジェット | jet-drive モデルのジェットの半幅 b = 2h/5 は、歌口の短いリコーダー（W/h ≈ 4）の値で、オルガン（W/h が 10 以上）では有効性が議論されている（[Auvray ほか 2014](https://www.researchgate.net/publication/263746590_Time-domain_simulation_of_flute-like_instruments_Comparison_of_jet-drive_and_discrete-vortex_models)）。ジェットは歌口を渡るあいだに広がり、上唇での振れは自分の幅を超えると渦に巻き上がって成長が止まる（Fletcher、[C. Pykett：The physics of voicing organ flue pipes](http://www.colinpykett.org.uk/physics-of-voicing-organ-flue-pipes.htm)） |
| プリンシパルの音色の実測 | 第2倍音は基音の −15〜+6 dB（17 世紀北ドイツで −9〜−15 dB）。強い倍音は 4〜6 本で、その上は 1 オクターブあたり約 −24 dB で落ちる。上唇とジェットのずれで非対称なパルスになり偶数倍音が出る（ずれがないと奇数倍音だけで、フルート的）（[C. Pykett：The Tonal Structure of Organ Principal Stops](http://www.colinpykett.org.uk/principals1.htm)、[The Effect of Organ Pipe Scales on their Harmonic Spectra](http://www.colinpykett.org.uk/effect-of-organ-pipe-scale-on-harmonic-spectra.htm)） |

### ビリビリの原因

鍵盤全体（C〜c⁴ の 61 鍵、残響なし）の倍音と波形を測りました。

- **c¹ から上は方形波でした。** ジェットの振れが上唇で半幅の 5〜9 倍もあり、内と外へ弁のように切り替わっていました。第5〜12倍音がそれぞれ −20〜−25 dB で平らに残り、合計で基音の −13〜−19 dB です（実測のプリンシパルは 1 オクターブあたり約 −24 dB で落ちる）。リードやブザーのような音です。
- **オクターブ（第2倍音）がない。** 切り替わりが上唇に対してほぼ対称なので奇数倍音ばかりになり、さらに歌口と管頭の音を道のりの差なしに足していたため、両端で逆向きのオクターブが打ち消されていました（出力の第2倍音 −17〜−40 dB）。
- **低音のざらつき。** C〜F は倍音と雑音の差が 23〜29 dB しかなく、切り替わりのたびに乱流の雑音がまとまって出ていました。

### 変えたこと（音源の物理）

1. **整音の圧力を基準の 500 Pa にしました。** 切り上げは整音数（Ising）2.0（低音）〜2.4（高音）で 500 Pa から決めます。文献の範囲（1/3.4〜1/4）に入りました。
2. **ジェットは歌口を渡るあいだに広がります**：b = b0 + s x。広がりの速さ s はジェットのレイノルズ数 Re = U_j h / ν で決まり、Re 500 以下（層流、高音域）で 0、2000 以上で 0.04 です。基準の風で C は Re ≈ 1700、c³ は ≈ 650 です。気体や温度（粘性）、風圧でも変わります。
3. **上唇でのジェットの振れは、自分の幅の 2.5 倍で頭打ちになります。** 波の振幅が飽和するので、1 周期の中ではなめらかな波のままです。手順1の「増幅は e⁴ まで」の上限は、振れを抑えるものがほかになかったための仮のもので、e⁶（低音を 5〜15 倍まで駆動する上限）にしました。
4. **上唇は、届いたジェットの半幅の半分だけずらしてあります**（Labium offset の初期値 0.5 b0 に、広がりの半分 0.5 s W を加えた位置）。ジェットのパルスが非対称になり、プリンシパルのオクターブが出ます。Labium offset のつまみは以前と同じく上唇を mm で動かします（表示も同じ）。
5. **管頭の音は、管の長さ × sin 27.5°（残響の部屋の聴き手がオルガンを見上げる角度）だけ遅れて届きます。** 左右の混ぜ方（歌口 0.85・管頭 0.35 など）は手順1のままです。

s = 0.04、2.5 倍、半分という値は、文献の物理の範囲（層流と乱流の中間の広がり、振れは幅程度で飽和）の中で、プリンシパルの実測の音色（上の表）に合うように選びました。これらを 0 にし、整音の圧力を 75 mmWS、管頭の道のりの差を 0 にすると、v0.6.3 の音（手順1のモデル）にそのまま戻ります（試験の port と tone で使っています）。

## Wind pressure（v0.6.1）

- MIDI CONTROLLER のつまみ 5「Wind pressure」は、それまでの **Bellows（ふいご）パラメータ**です（DAW のパラメータ ID は ``bellows``、名前は「Wind pressure」）。WIND 欄から Bellows はなくなり、Trem rate と Pallet speed の 2 つになりました。
- 値は **0.00〜5.00**、**1.00 = 500 Pa**（風箱の圧力 = 500 Pa × 値）。初期値は 1.00 です。DAW には「1.00 (500 Pa)」と表示し、「600 Pa」と入力しても受け付けます。
- つまみの動き：**0.00〜1.00 はつまみの最初の 2/3 で、以前の Bellows（0〜1.5 を直線）と同じ速さ**です。1.00〜5.00 は残りの 1/3 で、等比（同じだけ回すと同じ倍率）です。
- 以前の mmWS の「Wind pressure」パラメータ（10〜1000 mmWS）はなくなりました。基準の 500 Pa は固定です。
- コントローラー：つまみ 5（CC93）、フェーダー 1（CC82）、エクスプレッションペダル（CC11）がこのパラメータを動かします。パッド A1（風圧 ×5）とパッド B（風のパイプ）は以前のままです。マトリクスの行き先「Wind pressure」もこのパラメータです。
- パイプは v1.0.0 から基準の 1.00（500 Pa）で整音してあります（整音数 2.0〜2.4。v0.6.x は 75 mmWS = 735 Pa = 1.47 で整音）。緑の帯はバロック期のオルガンの例 69〜97 mmWS = 1.35〜1.90 です。
- 0.6.0 で保存したプロジェクト：Bellows の値はそのまま（同じ数値）読み込まれ、mmWS の Wind pressure の値は無視されます。
- レシピの風の値は新しい目盛りに直しました（2：0.43、4：1.00 → 5.00、19：2.16）。最大の 5.00（2500 Pa）では標準の整音のパイプはオーバーブローしないので、レシピ 3 と 13 は風 5.00 に加えて歌口を低く切り（カットアップ ×0.65）、オーバーブローさせています（v1.0.0 では C〜c² の全体、v0.6.x は c から下）。

**側孔とピッチロック**：側孔は「音孔」として扱います。開けると共鳴が上がり（管の中ほどで最大）、ピッチロックはジェットによるずれだけを取り除くので、鍵盤の音に**側孔の音程が正確に加わります**。ピッチロックで「側孔を開けても鍵盤の音」にする（管を長くする）と、穴が2番目のモードの節の近くに来て、パイプがその非整数倍のモードで鳴ってしまう（別の楽器になる）ためです。導波管の側孔の音程は、2本の管と分岐のモデル（`holeRatio`）と 1〜5 セントで一致しました。

### 変調マトリクス

4つのスロットがあり、それぞれ「ソース × 量」で1つのつまみを動かします。量はそのつまみの**目盛りの全幅に対する割合**です（+100 % でソースが 1 なら、スライダーの端から端まで）。

- ソース（11）：ベロシティ、鍵（c¹ = 0、±4 オクターブで ±1）、LFO 1・LFO 2（正弦）、エンベロープ（ノートごと：アタック後に減衰）、モジュレーションホイール（CC1）、プレッシャー（チャンネル／ポリ・アフタータッチ）、**パイプ自身の状態**＝音量（40〜100 dB SPL）、**オーバーブロー**（上の倍音で鳴っている）、**音程のずれ**（鍵盤から ±50 セント）、ランダム（ノートごと）。
- 行き先（27）：風圧、カットアップ、上唇位置、スケール、開管↔閉管、気体、温度、トレムラント、歌口の幅、乱流、足穴、グライド、側孔、音速、密度、FM の深さ・比、ジェットの帰還、クロスドライブ、波の速さ、エッジトーン、立ち上がりのパルス、ニッキング、壁の損失、打点、ダンパー、管壁の厚さ。
- **パイプごと**に計算します（ベロシティ、鍵、エンベロープ、音量、オーバーブロー、音程のずれはそのパイプのもの）。64 サンプルごとに目標を更新し、パイプは約 12 ms でなめらかに追従します（オーディオレートの変調は物理FM が受け持ちます）。
- 例：**Overblow → Open/Stopped +100 %**（計画の「オーバーブローした瞬間に閉管へモーフする」）。強い風でオーバーブローした瞬間に管頭が閉じます。試験では c（MIDI 48、Wind pressure 5.00・カットアップ ×0.65）でオーバーブローの検出 1.00、管頭は 100 % 閉じました。

### 最適化

- **AVX2 + FMA**：叩いた管壁のモード（最大 64 個の複素回転）を 4 つずつ計算します。この PC（Ryzen 5 3500U）で SSE2 の **1.5〜1.6 倍**、結果の差は 1e-15 です。残響の周波数領域の積和も AVX2 にしましたが、メモリ帯域で決まるため、この PC ではほとんど速くなりません（0.97〜1.09 倍）。CPU は起動時に一度だけ調べます（環境変数 `OKL_NO_AVX2=1` で SSE2 に固定）。
- **ジェットの揺らぎ**（下の「風圧と音量」）の 7 タップの読み出しを整理し、揺らぎによる追加の負荷を 1 ボイスの約 23 % から約 10〜20 % に減らしました。
- そのほか：残響のインパルス応答はサンプルレートごとに一度だけ計算して共有、FTZ/DAZ（非正規化数の処理を省く）を音源の処理中だけ有効にしています。

### 仕上げの検証で見つけて直したこと

全項目の試験（ランダム総当たり、ピッチロック、低い風）を最後まで通す中で、次の問題が見つかり、直しました。

| 見つかったこと | 原因と直し方 |
|---|---|
| 試験プログラムが 8 GB のメモリを使い、PC が止まりかけた | 手順1の C コアと比べる試験が、パラメータの並びを C++ 側の長さ（Mallet と手順5で増えた分を含む）で渡していました。C コア自身の長さで渡すようにしました（プラグイン本体には関係ありません） |
| 閉管の c が 1.1 kHz の別の音で鳴った | ジェットの揺らぎ（7 タップのガウス平均）は、タップの間隔ごとに応答が繰り返し、そこでは減衰しません。タップの前に 2 段の低域通過（タップ間隔の 0.4 倍の周波数）を入れて、その山を 17 dB 下げ、遅れを読み出し位置で補いました |
| 管長の物理FM をかけたパイプが、離鍵後も鳴り続けた | オーディオレートで長さが動く管は、自分の共鳴をパラメトリックに励振します。物理FM は鍵を押している間の実験として、離鍵（と打鍵モード）で 12 ms かけて止めるようにしました |
| マトリクスが管の長さや音速を動かし続けると、離鍵後も鳴り続けた | マトリクスは鍵（またはペダル）が押さえている間だけパイプを動かし、離鍵後のパイプはその形のまま減衰するようにしました |
| 側孔を開けた管が、閉じた管より長く鳴った | 管壁の損失は管頭のフィルタにまとめてあるので、側孔と歌口の間を往復する波は損失を受けませんでした。側孔から歌口へ戻る波に、その区間の分の損失を与えました。また、側孔の分岐を管の両端から 4 サンプル以上離し、側孔や管の端が 1 サンプル動いた瞬間は、その 1 サンプルだけ素通りさせるようにしました（同じ波を 2 度散乱させない） |
| 開管で、離鍵後もナイキスト周波数の振動が残った | 開管↔閉管のオールパスは、開管では係数がほぼ 1（極が −1 にほぼ乗る）で、状態に残った成分が消えませんでした。開管では恒等写像そのものにしました（音は変わりません） |
| 閉管の低い C でピッチロックが 3〜5 セント残った | ピッチのサーボが「正しい倍音を聴いているか」を測る基準に、息の高い雑音が入っていました（放射音は周波数に比例して高域が強い）。基準を帯域の 6 倍で低域通過して、0.14 セントで合うようにしました |

## Mallet モード

パイプの胴を硬いマレットで叩くモードです（WIND / MALLET で切り替え。DAW のパラメータ Excitation）。すべて物理モデルです。

- **管壁**：Flügge のシェル方程式（3×3）と梁関数で、円筒の曲げ・楕円・呼吸モードを求めます。材料は 5 種類（30 % 錫のコモンメタル、50 % のスポッテッドメタル、75 % 錫、亜鉛、銅）で、ヤング率・密度・内部損失は材料表から。管内外の気体による付加質量と放射（ベッセル関数）、熱弾性減衰を含みます。
- **マレット**：頭は 4 種類（硬いゴム、アクリル、ツゲ、真鍮）。ヘルツ接触と Hunt–Crossley の減衰で、接触時間と力が速さ・材料・大きさで決まります。ベロシティ = マレットの速さ（0.1〜3 m/s）。
- **空気柱**：管壁の呼吸が管内の空気を押し、管の共鳴（WIND と同じ導波管）も鳴ります。
- 鍵を離すとフェルトのダンパーが当たります（Damper、ペダルで保持）。叩いたパイプに効かないつまみ（風・ジェット関係）は画面で薄くなります。側孔は空気柱に効きます。
- 試験：材料ごとの減衰、接触時間、打点と節、つまみの効き方（風・ジェットのつまみは変化ゼロ、管・材料・マレットのつまみは変化）を確認しています。32 本を同時に叩くと、最初の 1 秒はこの PC の 1 コアの 60〜100 % です（測ったときの PC の状態で変わります。打った直後の接触の計算が重く、鳴っているあいだはずっと軽くなります）。

## 風圧と音量（WIND モードの物理の見直し）

非常に弱い風でも大きく鳴る、という問題を直しました。原因は、ジェットが歌口を渡る時間が一定のままで、弱い風で別の（エオリアン的な）発振が大きく鳴ってしまうことでした。実際のジェットは乱流で、渡る時間に揺らぎがあります。これを入れました（**渡る時間の標準偏差 0.35 τ**、7 タップのガウス平均）。

- 結果（c¹、ピッチロックなし、v1.0.0）：5 mmWS で 41 dB（息とかすかな音）、20 mmWS で 64.7 dB（−7.9 セント）、30 mmWS で 67.1 dB（0 セント）、75 mmWS で 70.8 dB、300 mmWS で 75.7 dB。風圧が 2 倍で約 +3 dB という実測（Verge 1997）に沿っています（v0.6.x：5 mmWS 31 dB、20 mmWS 63.9 dB、75 mmWS 71.6 dB）。
- 回帰チェック（`labium_check wind` の 2c）：プラグインと同じ音源全体の経路・ピッチロック 100 % で、5 mmWS が 75 mmWS より 20 dB 以上小さいこと、風とともに単調に大きくなること、風圧 2 倍あたり 1.5〜6 dB であることを確かめます。揺らぎのない以前のジェットではこのチェックに落ちることも、同じ試験の中で確かめています。

## 残響（物理的な部屋）

電子的に聞こえた FDN の残響をやめ、**教会の身廊を計算したインパルス応答**のたたみ込みにしました。

- 部屋：長さ 34 m・幅 16 m・高さ 16 m。西のギャラリーにオルガン、身廊の中ほどで 0.6 m 間隔の無指向性マイク 2 本。壁・窓・床（会衆席）・天井の吸音率は帯域ごと。
- 初期反射：鏡像法（周波数で変わる吸音、散乱 0.3、ISO 9613-1 の空気吸収）。後部残響：Eyring の T60 を帯域ごとに求め、拡散音場のエネルギー密度（4πc/V）で STFT 合成。左右のマイクの相関は sin(kd)/kd。
- T60：63 Hz 5.7 s、125 Hz 4.9 s、250 Hz 4.1 s、500 Hz 3.4 s、1 kHz 3.1 s、2 kHz 2.7 s、4 kHz 2.2 s、8 kHz 1.1 s。最初の反射 5.3 ms、残響音／直接音 +7.8 dB。
- たたみ込みは 4 段の分割（64・256・2048・4096 点）で遅延なし。CPU は 1 コアの約 2〜3.5 %。DAW に知らせるテール長は 6 秒です。

## 前提と制限

- **側孔はピッチロックで消えません**（上の「側孔とピッチロック」）。側孔の音程をなくしたいときは側孔を OFF にします。
- オーバーブローする風圧は音域で違います。v1.0.0 の標準の整音（500 Pa）では、ピッチロックなしで c が 200〜300 mmWS（2〜3 kPa）、c¹・c² が 300〜500 mmWS（3〜5 kPa）でオーバーブローします。Wind pressure の最大 5.00（2500 Pa）では標準の切り上げのまま基音で鳴るので、レシピ 3 と 13 は歌口を低く切っています（カットアップ ×0.65）。
- 極端な音域は物理どおりです。MIDI 0 の 20 m の管は標準の風では基音ではなく倍音で鳴り、MIDI 127 の極小の管はごく小さな音です。
- クロスドライブは 64 サンプル（48 kHz で約 1.3 ms）遅れて伝わります（空気を伝わる時間程度）。
- マトリクスは 64 サンプルごとの更新です（なめらかに補間）。オーディオレートの変調は物理FM を使ってください。
- CPU：ジェットの揺らぎ（弱い風を正しくするために入れたもの）の分だけ、手順4より 1 ボイスあたりの負荷が 1〜2 割増え、v1.0.0 のジェットと管頭の道のりでさらに約 7 % 増えました。32 音を全部鳴らし続けると、この PC の 1 コアの約 4〜5 割（電源接続時の見込み）、バッテリー駆動では約 6〜7 割です。
- v1.0.0 のジェットの広がり（0.04）・振れの頭打ち（幅の 2.5 倍）・上唇の位置（半幅の半分）は、文献の物理の範囲で、プリンシパルの実測の音色に合うように選んだ値です（上の「変えたこと」）。
- v1.0.0 は v0.6.3 より出力が平均 1.7 dB 小さくなりました（管頭の音が遅れて届くため）。必要なら Output level で上げてください。
- **ジェットの帰還（Jet feedback）を最大近く（×1.9 以上）にして風をごく弱く（100 Pa 前後）すると**、ジェットのループが振り切れ、安定化処理がボイスをリセットし続けることがあります（0.6.0 のランダム総当たり 240 回のうち 1 回。0.6.1 の総当たりでは起きませんでした）。出力は有限で止まりますが、プツプツした音になります。Lab の極端な組み合わせです。
- 巨大な管（音域外の低音）は、壁の損失が小さいと離鍵後も十数秒以上鳴り続けます（物理どおり、ゆっくり減衰します）。
- この PC では画面の 60 fps は安定しません（ホスト試験で平均 53 fps。バッテリー駆動では約 32〜35 fps）。音は画面を待たないので、途切れません。
- DAW と MiniLab 3 での確認は、上のチェックリストで行います。

## 手順1〜4からの変更点

| 変更 | 理由 |
|---|---|
| ピッチロックのサーボ | 鳴っている音程を各ボイスが測って管長を補正します（整律表の代わり）。オーバーブローや閉管では、その倍音を鍵盤の音程に合わせます。側孔があるときは、その分ずれた共鳴の位置で聴きます（v0.6.0） |
| 離鍵後の処理 | 極端な設定で「離鍵後も鳴り続ける」原因（ジェット速度の下限、足部の √ 流量則、渦損失の遅れ）を、離鍵後と不安定な領域だけ直しました |
| 損失フィルタの上限 | 極端な設定での発振を防ぐ上限（通常は働きません） |
| ジェットの揺らぎ（v0.6.0） | 弱い風での音量を物理に合わせるため（上の「風圧と音量」） |
| 整音の圧力（v1.0.0） | 基準の 500 Pa で整音（手順1は 75 mmWS）。切り上げが文献の範囲に入る（上の「Prinzipal の寸法の見直し」） |
| ジェットの広がりと振れの頭打ち（v1.0.0） | オルガンの長い歌口ではジェットが広がり、振れが幅で飽和するため。手順1のジェットは高音で弁のように切り替わり、方形波（ビリビリ）になっていました |
| 上唇の位置（v1.0.0） | 届いたジェットの半幅の半分だけずらす整音。非対称なパルスでプリンシパルのオクターブが出ます |
| 管頭の道のり（v1.0.0） | 両端の音を道のりの差なしに足していたので、オクターブが打ち消されていたため |
| 残響（v0.6.0） | 計算した身廊のたたみ込み（手順3・4の FDN をやめました） |
| サンプルレート | 70 kHz 未満は内部 2 倍、88.2・96 kHz は 1 倍 |
| 同時発音 | 32 音 |
| 画面 | 手順2の画面にプラグイン用の分岐を加えたもの。`pipe3d.js` の `setGeometry` は手順2のままです |
